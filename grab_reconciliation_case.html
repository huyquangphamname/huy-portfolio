Case Study: Finance Analytics · Data Reconciliation

Revenue Reconciliation Dashboard
(Marketplace × OMS × POS)

An order-level reconciliation dashboard that detects revenue discrepancies across three systems — the delivery marketplace, the order-management system, and the POS/accounting ledger — and lets finance drill any mismatch to its root cause.

Business Problem

Three systems recorded the same orders with misaligned schemas, keys and timelines — so revenue figures disagreed and there was no automated way to find which orders were off or why. Reconciliation was a slow manual cross-check.

Solution

A canonical order key chains the three systems together (marketplace → OMS → POS), standardizing 8 financial fields onto one schema and classifying every order into a reason code. A 3-layer Superset dashboard moves from overview to exception list to order-level detail.

Outcome

Replaced manual cross-checking with automated T+1 (marketplace ↔ OMS) and T+7 (OMS ↔ POS) cycles; finance can drill any exception from overview to order detail across all three systems.

How it works

Canonical key & union

Built a union mart at order × system grain, keeping each system's native id for drill-down while grouping on one canonical key.

Standardized schema

Normalized 8 finance fields (listing price, promotions, vouchers, shipping, customer-paid) and status/payment dimensions across all three systems.

Exception engine

A compare mart flags each order as MISSING_SOURCE / STATUS_MISMATCH / AMOUNT_MISMATCH / STORE_MISMATCH with the exact mismatching pair.

3-layer dashboard

A overview & cash flow → B exception list + KPI counters + trend → C order-level financial breakdown by source.
